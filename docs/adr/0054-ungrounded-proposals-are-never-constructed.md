# ADR 0054: Ungrounded proposals are never constructed; the cohort shares the
proposer's machinery

## Status
Accepted. Implements M8.

## Context
The proposer is built last, deliberately: every gate that constrains it now
exists. Building it earlier would have meant running an unconstrained
proposer, which is the thing the whole design exists to prevent.

Two decisions, and the second was nearly missed.

## Decision

**1. An ungrounded proposal is refused at construction, not rejected
downstream.** `Proposal.__post_init__` raises `UngroundedProposalError` when
`grounded_in` is empty. The distinction matters: a proposal that can be
*built* and then rejected will be built constantly, and every one consumes a
gate run, a rate-budget slot, and a line in the ledger. "It might help" is
not a reason any gate can weigh, so the object that would carry it does not
exist. A no-op proposal is refused for the same reason.

**2. Grounding may cite the train split only, and this is enforced
structurally.** The proposer is handed a `TrainOnlyEvidence` view rather than
the `Corpus`, so citing validation or holdout is not something it can do
incorrectly — only something it can fail to do at all. Citing validation
would let the proposer optimise against the set that gates it; citing the
holdout would destroy the owner's only independent read. `propose()` also
re-checks, because a view is a convenience and the rule is a requirement.

**3. The control cohort is generated by the proposer module, using the same
mutation machinery.** This is not organisational convenience. **A cohort
drawn from a different distribution than the candidate tests nothing about
the candidate** — if the candidate tweaks constants and the cohort perturbs
whitespace, beating the cohort proves only that constants matter more than
whitespace. So `ControlCohortGenerator` reuses `find_constants` and
`rewrite_constant`, differing from the real proposer in exactly one respect:
its values are random and it cites nothing.

**Cohort members are ungrounded by design**, which is why `is_control`
exempts them from rule 1. That is precisely what makes them a null
hypothesis: they are what "changes nobody reasoned about" score.

**The cohort is seeded.** A control cohort that cannot be reproduced cannot
be audited, and the whole point is that someone can re-derive the threshold
a candidate was measured against. A short cohort raises rather than
returning fewer members, which would silently weaken G3's threshold.

**4. Integer constants move by at least one whole unit.** Truncating
(`int(3 * 1.25) == 3`) made small integers silently un-proposable — a retry
limit of 3, exactly the kind of constant worth tuning, could never be
changed at all. Found by a failing test rather than anticipated.

## Consequences
- 27 tests. The anti-leak rule is tested for both validation and holdout,
  and the cohort's reproducibility is tested by generating it twice.
- Constants are found by **AST, not regex alone**, so a number inside a
  string or a nested scope cannot be rewritten. The rewrite then re-matches
  the target line and refuses if it does not look like the expected
  assignment.
- **The proposer is deliberately weak.** It changes module-level numeric
  constants and nothing else. That is a real limitation, not a stepping
  stone that will obviously generalise: an LLM-backed proposer changes no
  gate, but it does raise R3 (a plausible-but-harmful proposal) from Low to
  High, and it should not be built until M10's monitoring exists.
- G3 can now be supplied with a cohort, so the pipeline is complete in
  principle. It still must not auto-merge: M10 does not exist, so ADR 0045's
  Tier-2-until-M10 rule holds.

## Alternatives Considered
- **Emit ungrounded proposals and let a gate reject them.** Rejected: the
  queue fills with speculation, and each item costs a full gate run.
- **Generate the cohort by perturbing text or by shuffling the diff.**
  Rejected — different distribution, so the comparison would be
  uninformative in a way that is very hard to notice from the numbers.
- **Draw the cohort from previously-rejected proposals.** Rejected: those
  are not random, they are *selected for having failed*, which biases the
  threshold downward and makes the candidate look better than it is.
- **Let the proposer see validation to self-check before submitting.**
  Rejected: that is optimising against the gate, which is the definition of
  the leak the splits exist to prevent.

## Confidence
High on the grounding and split rules — both are enforced in code and
tested. High on the cohort sharing machinery, which follows from what the
comparison means. Medium-low on the proposer's *usefulness*: nothing yet
demonstrates that tuning numeric constants produces improvements worth the
machinery, and it may well not. That is the honest reading — the value of
M8 is that the pipeline is now end-to-end exercisable, not that this
proposer is good.
