## The adversarial pass, which is the part worth reading

A seam-hunter ran over the previous night's nine increments and reproduced
**ten** defects — seven for seven across this programme's history. Four
mattered:

1. **`aef run` never retrieved a consolidated lesson.** A fresh knowledge
   store per process, and the retrieve node runs before the consolidate
   node, so across CLI runs `retrieved_signatures` was always `[]` and
   helpful/harmful had no producer. ADR 0118's "A1 closed — the lessons the
   graph writes are the lessons it reads" was **false on the path the CLI
   actually runs**. Fixed by recomputing knowledge from the durable memory
   at run start (the consolidator is stateless by design, ADR 0110).
2. **The default retriever read every tenant's records.** `aef run --memory
   M` with no `context:` block built `MemoryRetriever(agent_id=None)` over
   the *durable* store — the exact widening an earlier adversarial round had
   already found once, reintroduced by ADR 0118's own default. Reproduced
   with another tenant's record. Fixed; ADR 0118 carries the erratum.
3. **The harness policy never reached the isolated node worker** (present
   since ADR 0094). Any adopter whose nodes consult the policy engine scored
   0.0 for candidate, incumbent *and* every control, so G3 compared uniform
   zeros and the loop could never accept anything. In-process 1.0 vs
   isolated 0.0, reproduced. Fixed by extending I11's `configure` frame.
4. **Harvest rejected every model-calling run as leaking a secret** —
   wave B found this itself: the output scan read the cassette's own
   SHA-256 request digest as an `opaque_secret`. All twenty summary
   scenarios matched. Fixed, with a test that a real secret in a model's
   *reply* is still caught.

Also fixed: the tally counted success entries as harmful and missed chained
failures; the judges could not see the answer they were scoring (which is
why agreement was 3/18 and 9/18); `ClaudeCodeProvider` inherited the
operator's MCP schemas and global `CLAUDE.md` (211,470 input tokens per call
as issued, 4,684 with the isolation flags); the prompt-surface filter hid
any forbidden phrase on a line containing "guide" or "remove"; redaction
turned a hyphenated English objective into a placeholder; the gates never
filtered the corpus by `graph_id`; `loop score` ran the incumbent with no
policy while `aef run --config` applied one; `run_loop` moved a checked-out
`loop/kept` and left a staged reversal.

And one that invalidated a previous night's evidence: **`run_loop` gave
every turn the same workdir**, and G1 refuses a non-empty workspace — so
every turn after the first was rejected by G1 before any behavioural gate
ran. ADRs 0114 and 0121 read those rejections as G3's. Both now carry
errata; the driver uses per-turn workdirs.
